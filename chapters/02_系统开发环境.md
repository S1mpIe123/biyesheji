# 2. 系统开发环境

## 2.1 计算机软件系统

### 2.1.1 计算机系统硬件配置

本系统在以下硬件环境下完成开发与测试：处理器为Intel Core i7-13620H，基准频率2.40 GHz，配备16 GB DDR4内存和512 GB固态硬盘，操作系统为64位Windows 11。该硬件配置能够同时支撑IntelliJ IDEA开发工具、Spring Boot后端服务、Vite前端开发服务器和MySQL数据库服务的并行运行。在开发过程中，后端服务启动时间约3至5秒，前端热更新响应时间在1秒以内，数据库查询操作在合理数据量下保持毫秒级响应，整体开发体验流畅。上述硬件环境属于当前主流笔记本配置水平，表明本系统的开发和运行对硬件资源的需求处于常规范围，具备较好的环境普适性。

### 2.1.2 计算机系统软件配置

系统开发涉及以下软件环境：后端开发采用JDK 21作为Java运行环境，Maven 3.9作为项目构建与依赖管理工具，IntelliJ IDEA 2023作为主要集成开发环境。数据库采用MySQL 8.0，通过MySQL Connector/J驱动与后端服务建立连接，开发过程中使用Navicat作为数据库可视化管理工具。前端开发依赖Node.js运行时环境，使用npm作为包管理器，Vite 4作为构建工具和开发服务器，VS Code作为前端代码编辑器。版本管理使用Git，浏览器测试以Chrome和Edge为主。

后端服务运行于9090端口，配置文件application.yml中指定了数据库连接参数、MyBatis映射文件路径、文件上传大小限制（100MB）等关键配置。前端通过Vite启动开发服务器，默认端口为5173，通过Axios的baseURL配置将API请求转发至后端9090端口。前后端分离运行，开发阶段无需额外集成部署，接口调试通过浏览器开发者工具和console日志协同完成。上述软件工具均为开源或社区免费版本，无需购买商业授权即可满足全部开发需求。

## 2.2 Java概述

Java是由Sun Microsystems公司于1995年发布的一种面向对象的通用编程语言，后归属Oracle公司持续维护和演进。Java语言的设计遵循"一次编写，到处运行"的跨平台理念，通过Java虚拟机（JVM）将源代码编译为平台无关的字节码，再由各操作系统上的JVM解释执行，从而屏蔽底层操作系统的差异[6]。经过近三十年的发展，Java已形成涵盖Java SE（标准版）、Java EE（企业版，现更名为Jakarta EE）和Java ME（微型版）的完整技术生态，在企业级Web应用、大数据处理、云计算服务和移动开发等领域均有广泛应用。

Java语言在Web后端开发中的优势体现在以下几个方面：静态类型系统在编译阶段即可捕获类型错误，减少了运行时异常的概率；完善的异常处理机制和垃圾回收机制降低了内存管理的开发负担；丰富的开源生态系统为常见开发需求提供了成熟的技术方案。本系统后端选择Java 21作为开发语言，利用其虚拟线程（Virtual Threads）预览特性提升并发场景下的资源利用效率。后端代码按Controller、Service、Mapper三层组织：Controller层负责接收前端HTTP请求、校验参数并返回统一封装的Result对象；Service层承载核心业务逻辑，包括用户校验、供需审核、匹配计算、库存同步等规则；Mapper层通过MyBatis框架与MySQL数据库交互，完成数据的持久化读写操作。

## 2.3 Spring Boot概述

Spring Boot是由Pivotal团队（现归属VMware）基于Spring Framework构建的一套快速应用开发框架，其核心设计目标是简化Spring应用的初始搭建和开发过程[7]。Spring Boot通过自动配置（Auto-Configuration）机制，根据项目引入的依赖自动推断并配置 Spring 上下文，大幅减少了传统Spring应用中繁琐的XML或Java配置代码。内嵌的Tomcat、Jetty或Undertow容器使得应用可以打包为可独立执行的JAR文件，无需部署到外部Servlet容器即可运行，显著简化了部署流程。

本系统采用Spring Boot 3.3.1版本，该版本基于Spring Framework 6.1构建，全面支持Jakarta EE 10规范，要求JDK 17及以上运行环境。系统主要通过以下Spring Boot特性完成后端服务的构建：spring-boot-starter-web提供RESTful接口开发支持，包括请求映射、参数绑定、JSON序列化与反序列化等功能；MyBatis-Spring-Boot-Starter 3.0.3实现MyBatis与Spring Boot的无缝集成，通过配置文件指定Mapper XML路径和实体映射规则，避免了手动创建SqlSessionFactory的样板代码；PageHelper-Spring-Boot-Starter 1.4.6为分页查询提供了简洁的声明式接口，在查询方法前调用PageHelper.startPage即可完成物理分页，无需在SQL中手动编写LIMIT子句。系统整合了Hutool 5.8.25工具库用于字符串处理、日期格式化、文件操作等通用任务，减少了重复工具代码的编写。

后端接口采用统一的Result返回结构，包含code（状态码）、msg（提示信息）和data（业务数据）三个字段，前端根据code值判断请求是否成功并执行后续逻辑。全局异常处理器统一捕获Controller层抛出的业务异常和系统异常，将其转换为标准的Result格式返回，确保前端不会收到非结构化的错误响应，降低了前后端异常处理的耦合度。

## 2.4 Vue概述

Vue是由尤雨溪于2014年发布的一款用于构建用户界面的渐进式JavaScript框架[8]。与Angular的全栈式方案和React的函数式编程范式不同，Vue采用"渐进式"设计理念：核心库专注于视图层渲染和响应式数据绑定，生态库（Vue Router、Pinia、Vite等）按需组合，开发者可以根据项目复杂度灵活选择技术栈的深度。Vue 3于2020年正式发布，在Vue 2的基础上重构为Composition API编程模型，通过setup函数和响应式引用（ref/reactive）实现逻辑复用和代码组织，同时保持对Options API的向后兼容。

本系统前端采用Vue 3.3.4版本，基于Composition API组织组件逻辑。前端项目通过Vite 4.4.11进行构建，Vite利用浏览器原生ES模块导入能力实现开发阶段的即时冷启动和模块热替换，避免了传统打包工具（如Webpack）在大型项目中逐步累积的构建延迟问题。页面路由通过Vue Router 4.2.5管理，路由表按功能模块组织，包括登录注册路由、商城首页路由、供应大厅路由、采购需求大厅路由、匹配推荐路由、撮合记录路由、订单路由和分析看板路由等。路由守卫在用户访问受保护页面前检查本地缓存的用户信息，根据role和userType字段判断访问权限，未登录用户或权限不符的用户被重定向至登录页面。

界面组件层采用Element Plus 2.4.2，该组件库是Element UI在Vue 3生态下的升级版本，提供表格、表单、对话框、日期选择器、分页器、导航菜单、标签页等六十余种组件。本系统前端页面大量使用el-table展示供应列表、采购需求列表、订单列表和撮合记录列表，使用el-form完成用户注册、供应信息填写、采购需求填写等数据录入场景，使用el-dialog承载审核操作、订单详情查看和撮合状态流转等弹窗交互。HTTP请求通过Axios 1.6.2库发送，前端在src/utils/request.js中创建统一的Axios实例，配置baseURL指向后端9090端口，设置请求和响应拦截器用于统一添加请求头和处理异常响应，各业务模块的API调用封装在src/api目录下，与页面组件解耦。

## 2.5 B/S架构与前后端分离概述

浏览器/服务器架构（Browser/Server，简称B/S架构）是Web应用领域的主流软件架构模式之一。与传统的客户端/服务器架构（C/S架构）相比，B/S架构将业务逻辑和数据存储集中在服务器端，用户仅需通过浏览器即可访问系统功能，无需在客户端设备上安装专用软件。这种集中式的部署和维护模式降低了客户端的配置要求，简化了系统升级和功能更新的操作流程，用户端的浏览器作为统一的交互入口，天然具有跨平台特性。

本系统严格遵循前后端分离的架构思想，将前端页面展示与后端数据处理解耦为两个独立运行的服务进程。前端基于Vue 3构建单页应用（SPA），在浏览器中完成页面渲染、路由跳转和用户交互，仅通过HTTP请求与后端交换JSON格式的数据。后端基于Spring Boot构建RESTful API服务，对外暴露数据查询和业务操作接口，不参与页面模板渲染和视图生成。前后端之间通过明确定义的接口协议通信：前端发送请求时携带路径参数、查询参数或JSON请求体，后端返回统一的Result封装对象，数据交互格式均为JSON。这种架构分离使得前端开发和后端开发可以独立进行——前端开发者只需关注页面交互和接口调用，后端开发者只需关注业务逻辑和数据处理，双方的开发进度互不阻塞。

在数据持久化层面，后端通过MyBatis与MySQL数据库交互。MyBatis将SQL语句与Java代码分离，SQL语句写入独立的XML映射文件中，便于DBA或开发者对SQL进行独立优化和调试。配置文件开启了下划线到驼峰的自动映射（map-underscore-to-camel-case），数据库字段（如user_name）自动映射为Java实体属性（如userName），减少了字段映射的重复配置。数据库选用MySQL 8.0关系型数据库，其事务支持（ACID特性）保证了订单支付、库存扣减和撮合记录状态变更等组合操作的原子性，行级锁机制在并发下单场景下提供了必要的数据一致性保障。
